Проверка выполнена 28 октября 2026 года локально на production-сборке Next.js,
доступной по `http://127.0.0.1:3000`. Браузер: системный Chromium
154.0.8037.57 (Debian), headless, Playwright 1.64.1. Конфигурация использует
изолированный браузерный контекст для каждого теста; гостевые ответы не
подменяются заранее подготовленным прогрессом.

Итоговый полный запуск `npm run test:e2e`: **15 passed (1.3m)**. Прогон
включает полный учебный путь, повторный экзамен, все перечисленные размеры и
инструменты, клавиатуру и отключение сети. Он повторён после финальной сборки
с исправленным контрастом, мобильными touch targets и Zod 4.6.7.

Дополнительно выполнены `npm run typecheck` (exit 0), `npm test` (**155 passed,
6 файлов**), `npm run build` (успешен, 30 маршрутов/страниц),
`npm audit --omit=dev --audit-level=high` (**0 vulnerabilities**) и
`git diff --check` (exit 0). Unit tests покрывают финансовую математику,
единицы, проверку ответов, сохранение/восстановление, версии, разблокировки,
дедупликацию, mastery и содержательные числовые примеры уроков.

## Настоящая авторизация и база

`npx playwright test --config playwright.auth.config.ts`: **1 passed (14.7s)**
на финальной production-сборке и настоящем отдельном Supabase-проекте
`iubwvalbydjxpvdmpocu`. Тест использует временный подтверждённый QA-аккаунт:
вход по паролю, импорт фактического гостевого UUID, подтверждённая синхронизация,
повторная загрузка без дубликатов, вход в чистом втором браузерном контексте,
тот же прогресс и выход без переноса аккаунта в гостевые данные. Ответы Auth
и RPC не подменяются. Credentials не входят в Git или browser traces.

Для воспроизведения создайте отдельный подтверждённый тестовый аккаунт в
FINLAB, задайте `FINLAB_TEST_EMAIL`/`FINLAB_TEST_PASSWORD` в окружении либо
игнорируемом `.env.e2e.local` и запустите указанную команду. Без этих переменных
тест явно пропускается. SQL-fixture подтверждён напрямую для проверки входа;
доставка регистрационного письма и переход по recovery email не проверялись.

Три SQL-миграции реально применены. `supabase/tests/security.sql` проверен на
удалённой БД: два пользователя, доступ только к своим данным, WITH CHECK,
SECURITY INVOKER views/RPC, запрет anon, атомарный merge/дедупликация,
старые/новые версии и ISO timestamps с часовыми смещениями. Результат PASS,
тестовые записи RLS-теста откатились. Security и Performance Advisors: `lints: []`.

## Воспроизведение

```sh
npm ci
npm run build
npm run test:e2e
```

Playwright сам запускает `npm run start` или использует уже работающий сервер.
Путь к системному Chromium можно задать переменной
`PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. Если системного Chromium нет, используется
стандартный браузер Playwright, который нужно установить отдельно.
`BASE_URL` позволяет проверить уже запущенное приложение.

## Проверенные пользовательские сценарии

- Первое открытие, четыре этапа onboarding и настоящая диагностика.
- Рекомендация стартового урока; публичный вход в первый урок каждого модуля.
- Блокировка последующих уроков и экзамена до выполнения условий.
- Чтение теории, формул и примеров; числовые, одиночные и множественные варианты,
  верно/неверно, сценарии и сопоставления.
- Некорректный числовой ввод не создаёт попытку. Неправильный валидный ответ
  получает объяснение принципа, а продолжение остаётся заблокированным.
- Незавершённый ответ и позиция восстанавливаются после перехода в библиотеку
  и перезагрузки страницы.
- Завершение первого урока, сохранение результата 80% с первой попытки,
  отсутствие повторного начисления после перезагрузки и переход к следующему.
- Полное прохождение **18 уроков и 3 экзаменов** реальными действиями браузера
  и проверка всех **112 упражнений**. Ключи ответов служат тестовыми входными
  данными; состояние прогресса тест не создаёт напрямую.
- Первый экзамен намеренно провален: три первоначальные ошибки исправляются,
  но итог остаётся ниже 70%. Проверено отсутствие перехода к следующему уроку
  на экране неуспешного результата; новая попытка даёт 100% и зачёт.
- После полного пути в сохранении 22 завершения (включая неуспешный экзамен)
  и 21 уникальный зачтённый этап. После перезагрузки путь показывает 21/21.
- Клавиатурой можно проверить числовой ответ и перейти дальше после успеха.
- Калькулятор сложных процентов: 100 000 ₽, 1 000 ₽ в месяц, год, нулевая
  ставка → 112 000 ₽; неконечный ввод показывает ошибку.
- PV: 121 000 ₽ через два года при 10% → 100 000 ₽; обратный FV → 121 000 ₽.
- Портфель: 60% × 10% + 40% × 5% → 8%; сумма весов 90% вызывает ошибку;
  явная нормализация восстанавливает расчёт; 60% × 10% + 40% × −5% → 4%.
  Добавление и удаление актива работают.
- Поиск терминов по-русски и по-английски, справочник формул, пустой результат
  поиска и его сброс.
- Смена темы и сохранение выбранной темы после перезагрузки.

## PWA и офлайн

Проверены ответ manifest и `display: standalone`, активация service worker,
появление ранее открытого урока в Cache API, затем полное отключение сети
браузерного контекста. Урок перезагружается из кеша и позволяет перейти к
следующему образовательному блоку.

Это проверка офлайн-доступа к уже загруженному публичному контенту. Она не
является проверкой установки на физический Android/iPhone, всей программы
без предварительной загрузки или доставки почты.

## Границы этой проверки

Основной набор в `tests/e2e/academy.spec.ts` проверяет гостевой режим в Chromium.
Настоящая авторизация, изоляция данных двух пользователей и синхронизация
Supabase проверяются отдельно; они не имитируются гостевыми тестами.
Safari/iOS, Firefox, физическая установка PWA и отправка регистрационных
писем этим набором не проверялись. Успешный локальный browser-run сам по себе
не подтверждает состояние опубликованного Vercel deployment.

HTML-отчёт Playwright находится в `playwright-report/`, диагностические файлы
ошибок — в `test-results/`. Эти каталоги исключены из Git.
